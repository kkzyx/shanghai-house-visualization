### 1.5 ⚠️ 使用这两个字段前必须知道的事

> 🔴 **`首付_万` / `月供_元` 与价格高度共线，不能和价格一起放进模型**<br><br>· `首付_万` = 价格 × **20% 或 30%**（两档），与 `价格_万元` 的 Pearson ρ = **0.947**<br>· `月供_元` 与 `价格_万元` 的 Pearson ρ = **0.997**（几乎是价格的单调变换）<br>· 而且 20%/30% 的档位**完全由区决定**（中心城区=20%，外围=30%），所以「首付比例」本质上是个**地理标记**，不是购房者行为<br><br>**它们可以用于展示**（「中位首付 87 万」对购房者比「中位总价 369 万」直观），**但不能当独立解释变量**。

> 💡 **`到市中心距离_公里` 与上面相反 —— 可以用**<br><br>判断原则：**派生自「自变量」的字段可以用；派生自「因变量」的字段不能用**。<br>· `到市中心距离` 派生自 **坐标**（解释房价的输入）→ ✅ 合法空间变量，与单价 ρ = **−0.705**<br>· `首付` 派生自 **价格**（我们想解释的结果）→ ❌ 等于「用价格解释价格」<br><br>**注意**：`到市中心距离` 是 `(经度, 纬度)` 的确定性函数，三者不要同时放进一个模型。


## §2 两种使用方式：用原始表 还是 用预计算表

同样的三个 Dashboard，有两条技术路线。**两条都能做出来，选一条即可，不要混着做。**


### 2.1 两种方式的差异

|  | **方式 A · 用 v2/ + v3/** | **方式 B · 用 tableau_ready/** |
|---|---|---|
| 数据源 | 只用 `v2/` 与 `v3/` 里的表 | 额外用 `tableau_ready/` 的 5 张预计算表 |

### ① 房价热力地图（1.5 km 网格）


#### 方式 B（推荐 · 省事）

```
1. 数据源连 tableau_ready/05_网格热力.csv（1,055 行，已聚合）
2. 列：[网格经度] → 右键设为「维度 + 连续」（绿色）
3. 行：[网格纬度] → 同样设为「维度 + 连续」
4. 标记类型：方形
5. 颜色：[中位单价]
6. 大小：拉到最大
7. 地图 → 地图层 → 背景地图 = 无
```


#### 方式 A（自己建网格）

```
[网格经度] = ROUND([经度] / 0.015753) * 0.015753
[网格纬度] = ROUND([纬度] / 0.013562) * 0.013562

筛选器：COUNT([单价_元每平]) >= 3
```

**这两个数怎么来的**：上海纬度 31.2°N 上，1° 经度 ≈ 95.2 km、1° 纬度 ≈ 110.6 km。要 1.5 km 的方格：经度步长 = 1.5/95.2 = **0.015753**，纬度步长 = 1.5/110.6 = **0.013562**。

> ⚠️ **经度必须做余弦修正**。地球是球体，经线越靠近两极越密 —— 1° 经度只有 1° 纬度的 **86.1%**。若两个方向用同一步长，格子会被拉成竖长条（高 16.9%）。

> 🔴 **这一步最容易错的三个地方**<br>1. **胶囊必须是「维度 + 连续」**（绿色）。若是蓝色离散，Tableau 会把 68 个经度值 × 78 个纬度值做成 **5,304 格的矩阵**，界面全是标题<br>2. **大小必须拉满**，否则方格之间有缝隙<br>3. **颜色用 `MEDIAN` 不是 `SUM`** —— 一格内可能几百条挂牌，求和就变成「挂牌量图」了


### 配色进阶：右偏分布下怎么让低端也有区分度

**问题**：上海单价是强右偏分布 —— 93.6% 的样本落在 5 千~10 万，而 20 万以上只占 **0.2%**。
在线性色阶（5,000 ~ 300,000）下：

| 分位 | 单价 | 落在色阶的位置 |
|---|---|---|
| P10 | 22,892 | 6.1% |
| P20 | 30,231 | 8.6% |
| **P50（中位）** | **48,342** | **14.7%** |
| P80 | 72,666 | 22.9% |
| P90 | 89,405 | 28.6% |

**P10~P50 这 40% 的样本，只占了色阶的前 15%** —— 中位数看起来和最低档几乎没区别。
但**中位数 4.8 万/㎡ 对普通购房者已经很高了**，不该被画成"接近最低"。

三个解法：

#### ① 封顶（最直接，推荐）

建一个计算字段把高端截断（以网格表 `05_网格热力.csv` 为例）：

```
[单价_封顶]
IF [中位单价] > 120000 THEN 120000 ELSE [中位单价] END
```

- **颜色**绑 `[单价_封顶]`
- **工具提示**仍放原始的 `[中位单价]`，读者看到的数值不失真

封顶值的选择：

| 封顶值 | 中位数落点 | 被封顶的样本占比 |
|---|---|---|
| 90,000 | 51% | 14.8% |
| **120,000（推荐）** | **38%** | **2.9%** |
| 150,000 | 30% | 1.0% |

> **为什么推荐 12 万**：中位数从色阶 14.7% 提到 38%，低端拉开明显；
> 而只有 2.9% 的极端值被封顶，都显示为最深红，不影响"哪里最贵"的判断。

#### ② 发散色板 + 自定义中心

```
右键颜色图例 → 编辑颜色
→ 选一个发散色板（如「红色-蓝色发散」）
→ 点「高级」→ 「中心」填 55000
```

这样 5.5 万成为颜色的分界点：低于它向蓝端铺开，高于它向红端铺开。
**注意**：发散色板的语义是"高于/低于某个基准"，不是"越贵越红"，
报告里要说明这个基准是什么。

#### ③ 分位数分档（最彻底）

按分位数分成 5 档，每档样本量相等（各 20%）：

```
[价格档位]
IF MEDIAN([中位单价]) < 30231 THEN '1 低（<3.0万）'
ELSEIF MEDIAN([中位单价]) < 42487 THEN '2 较低（3.0-4.2万）'
ELSEIF MEDIAN([中位单价]) < 54526 THEN '3 中（4.2-5.5万）'
ELSEIF MEDIAN([中位单价]) < 72666 THEN '4 较高（5.5-7.3万）'
ELSE '5 高（>7.3万）'
END
```

颜色绑 `[价格档位]`，用顺序色板（浅黄 → 深红）。
**优点**：最后一档从"0.2% 的样本"变成"20% 的样本"，颜色的面积和样本量匹配。

### Step 1 · 建三个权重参数

```
参数名：[教育权重]　数据类型：整数　当前值：33
允许的值：范围　最小值 0　最大值 100　步长 1
→ 勾选「显示参数控件」→ 选「滑块」

同样建 [医疗权重] = 33、[交通权重] = 34
```


### Step 2 · 区内 min-max 归一化（三个 LOD 计算字段）

```
[教育分]
IF { FIXED [区]: MAX([学校_500米]) } = { FIXED [区]: MIN([学校_500米]) } THEN 50
ELSE
  ([学校_500米] - { FIXED [区]: MIN([学校_500米]) })
  / ({ FIXED [区]: MAX([学校_500米]) } - { FIXED [区]: MIN([学校_500米]) }) * 100
END

[医疗分]
IF { FIXED [区]: MAX([医院_500米]) } = { FIXED [区]: MIN([医院_500米]) } THEN 50
ELSE
  ([医院_500米] - { FIXED [区]: MIN([医院_500米]) })
  / ({ FIXED [区]: MAX([医院_500米]) } - { FIXED [区]: MIN([医院_500米]) }) * 100
END

[交通分]
/* 步行时间越短越好 → 分子用 MAX 减，方向反过来 */
IF { FIXED [区]: MAX([步行时间_分钟]) } = { FIXED [区]: MIN([步行时间_分钟]) } THEN 50
ELSE
  ({ FIXED [区]: MAX([步行时间_分钟]) } - [步行时间_分钟])
  / ({ FIXED [区]: MAX([步行时间_分钟]) } - { FIXED [区]: MIN([步行时间_分钟]) }) * 100
END
```

> 🔴 **🔴 三个必须做对的地方**<br><br>**1. 必须是 `FIXED [区]`，不是 `FIXED [区],[小区]`**<br>后者是在**小区内**做归一化，而一个小区只有一行数据 → `MAX = MIN` → 所有分数都返回 50，地图全一个颜色。<br><br>**2. 除零保护必须有** —— 若某区所有小区的学校数相同，`MAX − MIN = 0`，会返回 `Inf` 或 `Null`。<br><br>**3. `[交通分]` 的分子要反过来** —— 用 `MAX − 当前值`，因为步行时间**越短越好**。


### Step 3 · 综合得分

```
[综合得分]
([教育分] * [教育权重] + [医疗分] * [医疗权重] + [交通分] * [交通权重])
/ NULLIF([教育权重] + [医疗权重] + [交通权重], 0)
```

`NULLIF(x, 0)` 防止三个权重全为 0 时除零。权重会先除以权重之和，所以三个滑块不必凑成 100。

## §7 常见坑速查


### 1. 地图坐标胶囊是蓝色（离散）

现象：拖 `网格经度` 到列后出现几百个列标题。**解决**：右键胶囊 → **连续**（变绿色）。


### 2. 双击经纬度后地图只有 1 个点

现象：地图上一个孤零零的点。原因：架子上是 `AVG(经度)`，对整张表求平均。**解决**：把 `小区` 拖到「详细信息」。


### 3. 用 Join 关联年鉴导致散点错误

现象：区级散点的气泡被房源数放大。**解决**：用**关系（Relationship）**，或直接用 `03_区级.csv` 单表。


### 4. 双轴图勾了「同步轴」

现象：户型的单价线被压成一条直线。**解决**：取消「同步轴」。


### 5. D3 的 LOD 写成 `FIXED [区],[小区]`

现象：得分地图全一个颜色、每个小区都是 50 分。**解决**：必须是 `FIXED [区]`。


### 6. D3 用了房源级表

现象：排名表里同一个小区出现几十行。**解决**：换成 `v3/02小区总表`（1,467 行）。


### 7. 箱形图须线不是 P95

Tableau 内置是 1.5×IQR，原型是 P5/P95。**解决**：接受差异并注明，或用 `06_箱形图分位.csv`。


### 8. Spearman vs Pearson

Tableau 内置 `CORR()` 是 Pearson。**解决**：用 `04_相关系数表.csv`，或按 §8.1 自己算。


### 9. 文本字段排序错乱

`房龄段`、`面积段` 默认按拼音排。**解决**：建数值排序字段。


### 10. 17 万行导致卡顿

**解决**：① 创建 .hyper 提取 ② 地图先加筛选器 ③ 用小区级表画地图。

### 8.1 Spearman 相关系数（8 个指标）

```
import pandas as pd
d = pd.read_csv('v2/01_房源级.csv', low_memory=False)
Y = pd.read_csv('v2/03_区级.csv', low_memory=False)

KEEP = ['地均预算收入_万元每平方公里','人均绿地_平方米','人口密度_人每平方公里',
        '每万人中学在校生_人','每万人卫生技术人员_人','人均居住房屋_平方米',
        '卫生机构_个','普通中学_所']

g = d.groupby('区').agg(中位单价=('单价_元每平','median'),
                        p25=('单价_元每平', lambda s: s.quantile(.25)),
                        p75=('单价_元每平', lambda s: s.quantile(.75))).reset_index()
g['区内分化'] = (g['p75'] - g['p25']) / g['中位单价'] * 100
g = g.merge(Y[['区'] + KEEP], on='区')

out = []
for c in KEEP:
    r = g[['中位单价', c]].dropna()
    out.append({'指标': c, 'ρ_vs_房价': round(r['中位单价'].corr(r[c], method='spearman'), 3)})
print(pd.DataFrame(out).sort_values('ρ_vs_房价', key=abs, ascending=False))
```

**实测输出**：地均预算收入 **0.976** · 人均绿地 **−0.924** · 人口密度 **0.918** · 每万人中学在校生 0.847 · 人均居住房屋 0.721 · 每万人卫生技术人员 0.715 · 普通中学_所 −0.121 · 卫生机构_个 0.000
