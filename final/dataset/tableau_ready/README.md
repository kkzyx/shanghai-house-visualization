## 逐个说明

### 04_相关系数表.csv

| 列 | 说明 |
|---|---|
| `指标名` | 中文显示名（如「地均预算收入」）|
| `字段名` | 在 `03_区级.csv` 里的原始列名 |
| `维度` | 经济财政 / 环境 / 人口 / 教育·人均 / 医疗·人均 / 住房供给 / 医疗·数量 / 教育·数量 |
| `相关系数_房价` | **Spearman ρ** vs 区中位单价 |
| `相关系数_分化` | Spearman ρ vs 区内分化 |
| `相关系数_房龄` | Spearman ρ vs 区中位房龄 |
| `稳健` | 是否通过 Bonferroni 校正（\|ρ\|>0.79）|

**8 个指标**：地均预算收入 +0.976 · 人均绿地 −0.924 · 人口密度 +0.918 · 每万人中学在校生 +0.847 · 每万人卫生技术人员 +0.715 · 人均居住房屋 +0.721 · 普通中学所数 −0.121 · 卫生机构个数 +0.000

**为什么需要它**：Tableau 的 `CORR()` 是 **Pearson**，不是 Spearman。虽然 16 个区、单调关系下两者接近，但为了和报告数字完全一致，直接用这张表。同时它解决了「多重比较」警示 —— `稳健` 列可以直接当筛选器。

**怎么用**：
```
列：[相关系数_房价]、[相关系数_分化]（两个度量并排）
行：[指标名]（按 |相关系数_房价| 降序）
标记：条形（分组）
```

### 05_网格热力.csv

| 列 | 说明 |
|---|---|
| `网格经度` / `网格纬度` | 已取整到 **1.5 km** 网格中心（GCJ-02）|
| `中位单价` | 该格内全部挂牌的中位单价 |
| `挂牌数` | 该格内挂牌条数（已筛 ≥3）|
| `小区数` | 该格内不同小区数 |

**格距换算**：经度 `1.5/95.2 = 0.015756`（已按 31.2°N 余弦修正）· 纬度 `1.5/110.6 = 0.013562`

**怎么用**：
```
列：[网格经度]  → 右键设为「维度 + 连续」（绿色）
行：[网格纬度]  → 同上
标记：方形
颜色：[中位单价]（用 MEDIAN 或直接拖，一格一行所以等价）
大小：拉到最大
```

**⚠️** 必须关掉背景地图（`地图 → 地图层 → 背景地图：无`），否则色块和底图打架。

### 06_箱形图分位.csv

| 列 | 说明 |
|---|---|
| `区` / `样本量` | — |
| `P05` `P25` `P50` `P75` `P95` | 五档分位 |
| `最小` `最大` | 极端值（一般不用，会被离群值拉爆）|
| `箱体下沿` | = P25 |
| `箱体高度` | = P75 − P25 |
| `下须长度` | = P25 − P05 |
| `上须长度` | = P95 − P75 |

**为什么需要它**：Tableau 内置盒须图的须线是 **1.5×IQR**，而预览页用的是 **P5/P95**。如果你想还原预览页，必须自建。

**怎么用（甘特条形图法）**：
```
列：[区]（按 P50 降序）
行：[箱体下沿]
标记：甘特条形图
大小：[箱体高度]
→ 再叠一层细甘特条画上须/下须
```

**如果不想折腾**：直接用 Tableau 内置盒须图（`分析 → 盒须图`），但在报告里注明须线是 1.5×IQR 而非 P95。

### 07_区内分化.csv

| 列 | 说明 |
|---|---|
| `区` `区中位单价` `区房源数` `区中位房龄` | 区级聚合 |
| `单价P25` `单价P75` | 分位 |
| `区内分化` | **= (P75 − P25) / 中位 × 100**，单位 % |

**区内分化**是一个**新的结果变量** —— 它衡量「这个区内部房价有多不均」。

**发现**：人均绿地 vs 区内分化 **ρ = +0.685** —— 绿地多的区（外围），房价低但**内部差距大**。

**怎么用**：
```
列：[人均绿地_平方米]（对数轴）    ← join 03_区级.csv 或直接用本表的区
行：[区内分化]
详细信息：[区]
标记：圆
```

### 08_D3小区级_打分用.csv

**1,467 行 × 21 列，一行一个小区** —— 这是 D3 打分的**正确粒度**。

| 列 | 说明 |
|---|---|
| `区` `小区` | 分组键 |
| `经度` `纬度` | 已从 `Longitude`/`Latitude` 改名，**完整率 100%** |
| **`学校_500米`** | 教育分来源 |
| **`医院_500米`** | 医疗分来源 |
| **`步行时间_分钟`** | 交通分来源（越短越好）|
| `挂牌数` `中位单价` `中位总价` `中位面积` `中位房龄` `到市中心距离` | 展示用 |
| `最近地铁站` `步行距离_米` | 交通参考 |
| `便利店_500米` `餐饮_500米` `商场_500米` `超市_500米` `生活便利度` `建筑类型` | 扩展分析用 |

**⚠️ 为什么必须用这张表而不是房源级表**

D3 的归一化用的是 LOD 表达式：
```
{FIXED [区]: MAX([学校_500米])}
```
如果表是**房源级**（一个小区几十行），`[学校_500米]` 会在小区内重复，`{FIXED [区]}` 仍然正确，但**排名表会出现几十行同一个小区**。

用小区级表（一行一个小区），排名表天然正确。

**⚠️ 每区小区数差异很大**

| 区 | 小区数 | | 区 | 小区数 |
|---|---|---|---|---|
| 浦东 | 301 | | 宝山 | 45 |
| 徐汇 | 255 | | 虹口 | 43 |
| 闵行 | 218 | | 黄浦 | 24 |
| 普陀 | 148 | | 奉贤 | 23 |
| 静安 | 88 | | **金山** | **9** |
| 松江 | 80 | | 长宁 | 60 |
| 嘉定 | 58 | | 杨浦 | 58 |
| 青浦 | 57 | | | |

**金山只有 9 个小区，做加权排名意义不大。** 建议在报告里说明：推荐功能适用于小区数 ≥50 的 11 个区。

## 怎么连进 Tableau

```
数据 → 新建数据源 → 文本文件
  → 选 04/05/06/07/08 中需要的表
  → 与主数据源按 [区] 建立「关系」（不要用 Join）
```

**注意**：
- `04` `06` `07` 是**区级**（16 行），与房源级关联必须用**关系**（Relationship），用 Join 会把区级值复制 17 万次
- `05` 是**网格级**，独立使用，不需要 join
- `08` 是**小区级**，D3 独立使用
