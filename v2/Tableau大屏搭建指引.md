## 1. 连数据（决定后面顺不顺）

**推荐：一个数据源，三张逻辑表用「关系（Relationship）」串联，不要用物理连接。**

1. 新建数据源 → 拖入 `01_房源明细` 作为主逻辑表
2. 拖入 `02_小区总表` → 关系设为 `区` = `区` **且** `小区` = `小区`
3. 拖入 `03_区表` → 关系设为 `区` = `区`
4. 右键 02 的 `Latitude` / `Longitude`（GCJ-02）→ 地理角色 → **纬度 / 经度**；`*_WGS84` 另建一组亦可，但**同一张图只用一套**
5. 右键 03 的 `区全名` → 地理角色 → **区**（切面图靠它匹配）

这样做的三个好处：① 明细图、小区图、区级图都能在同一数据源完成；② 关系式不会 join 放大，**天然避开 SUM 陷阱**（这是最推荐它的原因）；③ 维度层级 `区 → 板块 → 小区` 可直接下钻。

**若坚持用 `04_整合大宽表` 单表**：可以，但必须先在数据源里把**第 30–116 列**（小区级 47 列 + 区级 40 列）的「默认属性 → 聚合」改成 `MIN`（中位数类用 `MEDIAN`）。否则：

| 错误写法 | 结果 | 真实值 |
| --- | --- | --- |
| `SUM(年末常住人口_万人)` | 1,438,352 | 2,480.3 万（**放大 580 倍**） |
| `SUM(挂牌数)` | 37,892 | 5,850（放大 6.5 倍） |
| `SUM(挂牌单价_元每平)` | 330,664,986 | 无意义（单价不可加） |

**其他一次性设置**：单价 0 位小数、总价 0 位、百分比 1 位、生活便利度 0 位；`步行可达性` 与 `生活便利度等级` 右键 → **排序 → 手动**（否则按字典序排错）；数据源用「提取」即可（数据量极小）。

## 2. 大屏布局（固定 1920 × 1080）

```
┌──────────────────────────────────────────────────────────────────────┐
│  标题栏（全宽 72px）：主标题 + 数据口径/时间 + 参数控件（指标切换）      │
├────────┬────────┬────────┬────────┬────────┬────────────────────────┤
│ KPI 1  │ KPI 2  │ KPI 3  │ KPI 4  │ KPI 5  │ KPI 6                  │ 108px
│ 房源数  │ 小区数  │ 中位单价│ 中位总价│ 便利度 │ 地铁可达率              │
├─────────────────────────────┬────────────────────────────────────────┤
│ ① 区级切面图（地图）          │ ② 小区点图（地图，2,242 点）            │ 400px
├──────────────┬──────────────┼───────────────┬────────────────────────┤
│ ③ 圈层散点    │ ④ 便利度×房价 │ ⑤ 可达性分档柱 │ ⑥ 各区对比条形          │ 340px
├──────────────┴──────────────┴───────────────┴────────────────────────┤
│ ⑦ 区级社会经济 × 房价（散点/双轴）        │ ⑧ 小区排行榜明细表         │ 180px
└──────────────────────────────────────────────────────────────────────┘
```

- 组件全部用**平铺容器**（避免浮动错位）；容器内边距统一 8–12px，视图间距 4–8px
- KPI 卡用「文本表」只留一个数字（去掉行列标签、加浅色底框）
- 字号按观看距离放大：主标题 28–32pt、视图标题 16–18pt、轴与标签 11–13pt、tooltip 12pt
- 配色：地图用连续色阶（暖→冷或单色深浅），上限按第 0 节手动设定；分类维度用 Tableau 10；深色大屏背景建议 `#1F2430` 或 `#0F1419` 配白字，地图样式选「深色」

## 4. 交互联动（让大屏「活」起来）

- **筛选器**（统一放顶栏容器）：`区`（多选下拉）、`板块`、`是否中心城区`、`生活便利度等级`、`样本量是否充足`（**默认 True**）、`状态`（默认只看 `ok`）
- 每个筛选器右键 → 「应用于选定的工作表」，让 KPI 卡不随筛选变化（或反之，取决于你想要的口径）
- **操作（仪表板 → 操作）**：
  - 点地图某区 → 筛选其他视图（「筛选器」操作：源 = 切面图，目标 = ②③④⑤⑥⑦）
  - 悬停高亮（默认开启），大屏演示时很有用
  - 点小区 / 房源 → 「URL」操作跳转到 01 的 `链接`（仅明细层可加）
- **参数**（放顶栏）：
  - 指标切换：`CASE [指标] WHEN '中位单价' THEN [中位单价_元每平] WHEN '中位总价' THEN [中位总价_万元] WHEN '生活便利度' THEN [生活便利度] END`
  - Top N：`RANK(MEDIAN([中位单价_元每平])) <= [Top N]`
  - 对数轴开关：建议做两张工作表切换显示，而不是用参数控制轴
- **下钻**：在 02 上建层级 `区 → 板块 → 小区`，配参数或使用 Tableau 的「下钻」按钮

## 5. 三套主题方案（挑一个，不要全都堆上）

| 方案 | 主问题 | 需要的视图 | 数据支持度 |
| --- | --- | --- | --- |
| **A 房价的空间格局** | 上海二手房价格如何随区位 / 环线分异？ | ①②③④⑥⑦ | 最稳 |
| **B 生活便利度与配套公平性** ⭐ | 配套便利度是否存在价格溢价？哪些区域配套缺失？ | ⑤⑧ + 便利度等级分布 + 零配套小区地图（②换色） | **v2 新数据专为它而生**，最出彩 |
| **C 房价 × 区级社会经济** | 财政实力 / 老龄化 / 绿地与房价有什么关联？ | ⑧⑦ + 雷达图 + 双轴 | 用 03 的 16 行年鉴数据，注意样本仅 16 个区 |

推荐 **B 为主、A 为辅**：补全后的配套数据是这份数据集的差异化亮点，「生活便利度 vs 中位单价」散点能直接讲出一个有价值的结论。

## 6. 执行顺序与发布前自检

**第一版 30–45 分钟可完成：**

1. 连数据源 + 设地理角色 + 改默认聚合 / 排序（10 分钟）
2. 先做 4 张最核心的：切面图、小区点图、圈层散点、便利度 × 房价（15 分钟）
3. 拼大屏：固定 1920 × 1080，先摆 KPI 条和主图，用平铺容器对齐（10 分钟）
4. 加筛选器 + 点击联动 + 可视化 tooltip（10 分钟）
5. 统一字号、配色、数字格式，把第 0 节的 4 处极值色阶上限手动设定

**发布前自检 6 条：**

1. 有没有图用 `SUM` 去加单价 / 中位数 / 区级指标？
2. `步行可达性`、`生活便利度等级` 是否手动排序？
3. 金山是否被可达性图误判为最差（该区实际有市域铁路金山卫站）？
4. 排行榜榜首是否都是只有 1 条挂牌的小区（应叠加 `样本量是否充足` 过滤）？
5. 崇明、金山的区级指标是否因挂牌样本极少而失真（应标注样本量）？
6. 中文字体在别人机器上是否正常（建议 PingFang SC / 微软雅黑 / 思源黑体）？
