## 3. 项目主题与核心分析思路

画面中的核心模块标题为 `2020 Election Poll Simulation`。结合地区名称判断，该项目很可能以香港选举数据为背景，研究地区选民特征、模拟结果、人物表现及变量之间的关系。

项目采用的不是单一描述性图表，而是一套多层次分析结构：

1. 通过地图呈现选民或选区的空间差异；
2. 通过参数控制进行选举结果模拟；
3. 通过地区条形图比较不同选区的比例结果；
4. 通过散点图衡量人物或选项的表现；
5. 通过相关性热力图探索变量之间的关系；
6. 通过筛选器、下拉菜单和 Tooltip 支持用户自行探索。

可以将其分析逻辑概括为：

> 地区特征 → 条件选择 → 结果模拟 → 地区比较 → 表现评估 → 变量关系

这条逻辑链是本案例最值得学习的部分。它表明 Dashboard 中不同图表应承担不同分析任务，而不是为了增加图表数量而并列摆放。

## 4. Dashboard 结构分析

### 4.1 左上：`Voters characteristic` 地图

该区域使用分级着色地图呈现地理分布。地图中的区域采用多种颜色区分不同选区、群体、选择结果或指标水平。

视频中确认的功能包括：

- 地理区域着色；
- 地图缩放控件；
- 悬停 Tooltip；
- Tooltip 中显示选择项和相应数值；
- 地图状态会随筛选或选择发生变化。

地图适合回答的问题包括：

- 不同地区的选民特征是否存在明显差异？
- 某种选择、阵营或指标主要集中在哪些区域？
- 地理位置是否与模拟结果或表现指标有关？

地图的价值在于提供空间模式，而不仅是展示地名。如果新项目中的地理位置与研究问题没有实际关系，就不应仅为了视觉效果添加地图。

### 4.2 左下：`2020 Election Poll Simulation`

这是整个项目中最能体现技术深度的模块。画面中可见多个参数控件、模拟结果表格以及地区结果条形图。

该模块可能包含：

- 一个或多个条件滑块；
- 下拉选择器；
- 参数变化后的结果表格；
- 不同地区的比例结果；
- 两类结果的横向堆叠条形图；
- 总体或地区级别的汇总数值。

条形图列出了多个香港地理选区，例如：

- Hong Kong Island；
- Kowloon East；
- Kowloon West；
- New Territories East；
- New Territories West。

该模块说明，较强的 Tableau 项目可以超越静态历史描述，让用户调整假设并观察结果变化。Proposal 如果要采用类似设计，需要提前写清楚：

- 哪些字段是用户可调整的参数；
- 参数改变后哪些计算字段会更新；
- 模拟结果的计算逻辑是什么；
- 模拟的用途是预测、情景比较，还是教学演示；
- 结果是否有足够的数据依据，避免把简单筛选误称为预测模型。

### 4.3 右上：`Performance Metrics` 散点图

该区域使用带数据标签和趋势线的散点图。横轴可辨认为与 `Attendance` 有关，图中各点带有人物或选项名称。

这一图表可能用于分析：

- 出席次数与表现指标之间的关系；
- 哪些人物高于或低于整体趋势；
- 是否存在离群值；
- 高活动程度是否对应更好的选举表现。

散点图比简单排名表更有分析价值，因为它同时展示两个连续变量，并允许观察相关趋势和异常对象。加入趋势线后，用户可以快速判断变量之间的大致关系。

但图中的标签较多，部分名称重叠。更理想的设计是默认只标注关键点或离群值，其余信息通过 Tooltip 显示。

### 4.4 右下：相关性热力图

该区域使用红—黄—绿渐变的相关性矩阵，比较多个变量之间的关联程度。

热力图适合：

- 快速识别正相关和负相关；
- 找出高度相关、可能重复的信息；
- 为后续重点分析选择变量；
- 将多个变量的关系压缩在一个视图中。

该图增加了分析深度，但画面中的变量名称较密集，字号较小。对于一般用户，相关系数的含义也可能不够直观。因此正式项目应增加图例解释、关键关系标注或简短结论。

### 4.5 中间控制区

地图与右侧图表之间设置了较窄的筛选控制区。可观察到：

- `Display Type` 一类的显示模式选项；
- 多选复选框列表；
- 地区或对象选择；
- 数值型过滤或百分比过滤；
- 颜色图例。

这种集中式控制区可以让用户知道所有交互入口在哪里，但当前设计的问题是控件过多、空间过窄。用户可能难以判断哪些控件影响整个 Dashboard，哪些只影响某一张图。

## 5. 交互设计分析

### 5.1 已确认的交互

- **地图 Tooltip**：鼠标悬停后显示所选区域或对象的详细指标。
- **多选筛选器**：可以勾选多个对象，控制图表中显示的内容。
- **下拉菜单**：用于改变模拟条件或显示模式。
- **参数/滑块**：用于改变模拟输入或阈值。
- **地图缩放**：允许用户查看局部地区。
- **联动更新的可能性**：多个模块围绕相同主题和选择项组织，画面状态显示它们很可能共享筛选条件；但具体 Dashboard Action 配置无法仅凭视频完全确认。

### 5.2 交互设计的优点

- 交互与分析问题有关，而不是纯装饰；
- 用户可以从总体分布逐步深入到特定地区或对象；
- 参数控制使 Dashboard 具有“试验工具”的性质；
- Tooltip 将细节隐藏在需要时显示，减少主视图中的文字量；
- 不同图表提供互补视角。

### 5.3 交互设计的风险

- 控件数量过多会增加学习成本；
- 缺少操作说明时，用户可能不知道从哪里开始；
- 如果多个筛选器的影响范围不同，容易产生误解；
- 参数模拟如果没有解释计算方法，用户可能把情景结果误认为可靠预测；
- 单页承载过多任务，可能造成视觉和认知负担。

## 6. 视觉与信息设计评价

### 优点

1. **结构完整**：地图、模拟、比较、绩效和相关性形成较完整的分析系统。
2. **图表类型匹配分析任务**：空间问题使用地图，双变量关系使用散点图，多变量关系使用热力图，比例比较使用条形图。
3. **布局具有基本分区**：左侧偏向选民与模拟，右侧偏向绩效和关系分析。
4. **技术元素丰富**：项目展示了 Tableau 的地图、筛选器、参数、Tooltip、趋势线和计算结果等能力。
5. **同一主题下的多视角分析**：各模块不是完全无关的独立图表。

### 不足

1. **信息密度过高**：四个主要图表、一个模拟面板和大量筛选器同时出现。
2. **字体偏小**：图表标题、坐标、人物名称和变量名称在正常观看尺寸下较难阅读。
3. **视觉层级不足**：缺少突出的项目总标题、核心指标和阅读起点。
4. **颜色语义不完全一致**：地图、地区条形图和热力图采用不同色系，但缺少明显的统一说明。
5. **标签拥挤**：散点图中的名称和热力图中的变量标签较密集。
6. **结论表达较弱**：Dashboard 更像探索工具，没有明显突出“最重要的三项发现”。
7. **缺少用户指引**：没有清楚显示“先选择什么、再观察什么”。

## 7. 数据故事与展示逻辑

从视频画面看，项目展示方式主要是围绕一个综合 Dashboard 操作，并未明显切换到多个 Story 页面。因此，它的强项是分析工具和交互演示，弱项是线性叙事。

可以从现有结构中读出潜在故事顺序：

1. 先了解选民在不同地区的空间特征；
2. 调整模拟参数；
3. 比较五个选区的结果；
4. 检查人物或对象的表现；
5. 使用相关性矩阵解释可能的影响因素。

但这个顺序主要依靠用户自行理解。更好的版本可以增加：

- 一个明确的问题式标题；
- 2–3 个总体 KPI；
- 编号式阅读顺序；
- 关键发现注释；
- “重置筛选”按钮；
- 对模拟方法和相关性的简短解释；
- 一个结论页或 Summary 区域。

## 9. 对新项目 Proposal 的直接启示

### 9.1 Proposal 应先写分析问题，再写图表

不要只写：

> 我将制作地图、柱状图、散点图和 Dashboard。

更合适的写法是：

> 本项目将首先比较不同地区的目标指标分布，再分析指标与关键影响因素之间的关系，并允许用户通过时间、地区和类别筛选探索不同情景。地图用于识别空间差异，条形图用于比较类别，散点图用于检验变量关系。

### 9.2 建议形成完整逻辑链

Proposal 中的内容应满足：

> 核心问题 → 子问题 → 所需数据 → 可视化方法 → 交互方式 → 可获得的发现

可以使用下表规划：

| 子问题 | 数据字段 | 图表 | 交互 | 预期作用 |
|---|---|---|---|---|
| 哪些地区表现较高或较低？ | 地区、指标值、时间 | 地图 | 地区和时间筛选 | 识别空间差异 |
| 不同类别之间有何差异？ | 类别、数量、比例 | 排序条形图 | 类别筛选 | 完成横向比较 |
| 哪些因素与结果有关？ | 结果变量、影响变量 | 散点图 | 高亮和 Tooltip | 观察趋势和离群值 |
| 多个变量之间如何关联？ | 多个数值字段 | 热力图 | 变量选择 | 识别相关结构 |
| 条件变化后结果如何变化？ | 参数、计算字段 | 参数化视图 | 参数控件 | 进行情景比较 |

### 9.3 交互功能必须有明确用途

Proposal 不应简单承诺“大量交互”。每个交互都应回答一个用户任务：

- 筛选器：缩小分析范围；
- 参数：改变假设或计算方法；
- Highlight：比较选中对象与整体；
- Dashboard Action：从概览进入细节；
- Tooltip：提供按需细节；
- Reset：恢复默认分析状态。

### 9.4 控制项目范围

本案例的复杂度较高，但新项目不必复制所有功能。更现实的范围是：

- 1 个明确主题；
- 3–5 个具体分析问题；
- 2–3 个 Dashboard 或一个分层清楚的综合 Dashboard；
- 4–6 种真正有用途的可视化；
- 2–4 个核心交互；
- 3 项能够通过数据支持的主要发现。

## 10. 值得学习与不应照搬的内容

### 值得学习

- 围绕一个核心主题组织多种分析视角；
- 将地图、比较图、关系图和模拟模块分配给不同问题；
- 使用参数和计算字段实现情景分析；
- 通过 Tooltip 和筛选器支持由概览到细节的探索；
- 同时考虑描述性分析和关系分析；
- 让 Dashboard 能够支持用户主动提问。

### 不应照搬

- 直接复制选举主题、数据或地区划分；
- 为体现技术复杂度而堆叠过多图表；
- 在狭窄区域放置大量复选框和参数；
- 在散点图上显示所有名称；
- 使用相关性热力图却不解释变量和颜色；
- 只展示交互功能，不明确项目发现和用户价值；
- 把筛选结果或简单计算称为预测模型。

## 12. 最终结论

该案例展示了一个高完成度 Tableau 项目应具备的核心特征：它不是若干独立图表的集合，而是围绕同一问题建立的交互分析系统。地图负责解释空间差异，模拟模块允许用户改变条件，条形图用于比较地区，散点图用于分析表现与影响因素，热力图用于揭示变量关系。

它对新 Proposal 最重要的启示是：

> 应当先定义用户需要解决的问题，再为每个问题选择数据、图表和交互；技术功能必须服务于分析逻辑，而不是成为项目目标本身。

如果在借鉴其分析深度的同时，减少页面拥挤、统一颜色语义、加强阅读顺序并突出关键发现，新项目会比该案例更清晰、更易用，也更容易在 Proposal 中证明其价值和可行性。
